# 글모아 — 손글씨 폰트 스튜디오

화면에 쓴 글씨를 모아 한글 TTF로 만드는 브라우저 기반 프로토타입입니다. 폰트를 만들 때 저장된 획 경로를 크기 조정 **후** 일정한 굵기로 다시 그리는 벡터 보정을 기본 적용합니다. 안전하게 재현하기 어려운 부분은 이전 윤곽을 유지하며, 실제 적용·유지 내역을 결과에 표시합니다. 선택적으로 흔들림 정리와 글자 간격·띄어쓰기·세로 정렬도 조정할 수 있습니다.

시작 버튼을 누르면 글자 쓰기, 초성·중성·종성 색칠을 각각 별도 팝업에서 진행합니다. 자모는 자동 분리가 아니라 사용자가 직접 색칠하여 나눕니다. 받침이 없는 글자는 종성을, 숫자와 기호는 색칠을 생략합니다. 각 팝업은 화면 안에 맞추고 배경 스크롤을 잠급니다. 필기와 폰트 생성은 브라우저에서 처리하며 서버로 보내지 않습니다.

## 실행

Node.js가 있으면 번들된 워커를 이용해 바로 실행할 수 있습니다.

```bash
PORT=4176 node serve.js
# 브라우저에서 http://localhost:4176
```

소스를 변경하고 워커를 다시 만들거나 테스트하려면:

```bash
npm ci
npm run build
npm test
PORT=4176 npm start
```

Chromium과 Python `fonttools`를 설치하고 서버를 띄운 상태에서 다음 브라우저 테스트를 실행할 수 있습니다.

```bash
npx playwright install chromium
python -m pip install fonttools
APP_URL=http://127.0.0.1:4176/ npm run test:browser
APP_URL=http://127.0.0.1:4176/ npm run test:vector
APP_URL=http://127.0.0.1:4176/ npm run test:auto-vector
APP_URL=http://127.0.0.1:4176/ npm run test:auto-vector:full
APP_URL=http://127.0.0.1:4176/ npm run test:designer
APP_URL=http://127.0.0.1:4176/ npm run test:compat
APP_URL=http://127.0.0.1:4176/ npm run test:compat:full
APP_URL=http://127.0.0.1:4176/ npm run test:mobile
APP_URL=http://127.0.0.1:4176/ npm run test:modal
```

`test:vector`는 조절값 저장·재생성 안내, 굵기·정도에 따른 실제 TTF 변화, 전후 비교와 다운로드 TTF의 윤곽·간격 일치, 안전장치와 호환 모드를 검사합니다. `test:auto-vector`는 기본 적용과 끄기, 직접 쓴 글자와 조합·독립 자모, 숫자, 색칠 경계, 획 합침 위험과 기존 데이터 보존을 검사합니다. `test:auto-vector:full`은 합성 데이터로 11,172자 TTF를 만들고 모든 유지 윤곽과 20개 전후 미리보기 글자가 실제 결과와 일치하는지 검사합니다. `test:designer`는 간격·높이·흔들림 정리, `test:compat`은 작업자 차단과 백업·복원, `test:compat:full`은 11,172자 호환 모드를 검사합니다. `test:mobile`과 `test:modal`은 반응형 배치, 별도 팝업, 회전·스크롤 잠금·포커스, 합성 입력 및 실제 TTF를 검사합니다. `test:vector`, `test:auto-vector`, `test:auto-vector:full`, `test:compat`, `test:compat:full`, `test:mobile`, `test:modal`은 `TEST_BROWSER=firefox` 또는 `TEST_BROWSER=webkit`으로 다른 엔진을 선택할 수 있습니다. Playwright 자동 검사는 실제 모바일 기기나 물리 펜 검증을 대체하지 않습니다. 결과 TTF는 운영체제 임시 폴더에 저장되며 `STROKE_TEST_DIR`, `VECTOR_TEST_DIR`, `VECTOR_FULL_TEST_DIR`, `DESIGN_TEST_DIR`, `COMPAT_TEST_DIR`, `MOBILE_TEST_DIR`, `MODAL_TEST_DIR`로 위치를 바꿀 수 있습니다. `file://`에는 저장·보안·폰트 로딩 제약이 있으므로 HTTP로 서빙하세요.

## 실제 TTF의 벡터 획 굵기 자동 보정

- 폰트 만들기 단계의 **획 굵기 자동 맞춤**이 기본으로 켜져 있습니다. 각 직접 쓴 한글의 저장 획과 사용자가 칠한 마스크를 대조하고, 재현 가능한 직접 글자들의 크기 조정 후 펜 굵기 중앙값을 기준으로 삼습니다. 획 좌표를 글자 또는 자모 슬롯에 먼저 변환한 다음 둥근 획으로 다시 그리고 윤곽을 추적하여 **다운로드 TTF 자체**에 넣습니다. 외곽선을 침식하는 형태학적 보정이 아닙니다.
- **맞추는 정도**는 0~100%, **기준 굵기**는 내 글씨 기준 70~130%로 정합니다. 목표 폭은 안전한 범위(14~150 폰트 단위)로 제한될 수 있습니다. 각 획의 자연스러운 스케일 후 폭에서 목표 폭으로 정도에 따라 보간해 다시 그립니다. 0% 또는 토글 끄기는 기존 윤곽을 유지하고, 100%는 안전검사를 통과한 획을 기준 폭으로 맞춥니다. 중간 값도 획을 다시 그리므로 작은 값이라도 곡선·끝 모양이 조금 달라질 수 있습니다.
- **내 글씨로 전후 확인**은 색칠을 마친 내 한글을 사용합니다. 입력하지 않으면 직접 쓴 글자 중 최대 6자, 입력하면 서로 다른 한글 음절 최대 20자를 보여 줍니다. 조합하지 못한 글자는 표시하지 않고 알려 줍니다. 비교할 몇 글자만 조합해 속도를 줄이되, 기준 굵기를 정할 때는 완성된 입력 전체를 사용합니다. 실제 생성과 같은 흔들림 정리·간격·높이 설정, 색칠 및 획·자모 접촉 안전검사를 적용합니다. 보정 전과 현재 설정의 글자별 적용·유지 사유를 보여 주며, 별도 비교용 TTF를 실사용 결과로 제공하지 않습니다.
- 자모는 오직 사용자가 칠한 픽셀을 따라 저장 경로를 나눕니다. 나눈 경로가 색칠을 충분히 재현하지 못하거나, 원래 경로가 없거나 너무 복잡하거나, 굵기 변화가 지나치게 크거나, 재생성 시 획 덩어리·구멍 수 또는 면적이 크게 바뀌면 그 부분의 보정 전 윤곽을 유지합니다. 조합 시 서로 다른 자모의 획이 이미 닿아 있거나 새로 닿을 위험이 있으면 해당 음절 전체의 기존 윤곽을 유지합니다.
- 직접 쓴 음절도 같은 형태 안전검사를 통과할 때만 다시 그립니다. 직접 쓴 음절은 여전히 조합 음절보다 우선합니다. 독립 호환 자모는 원래 경로가 있으면 보정하고, 추정 자모는 원래 경로가 없으므로 기존 윤곽을 씁니다. 숫자·기호는 원래 윤곽을 유지합니다. 빠진 경로가 있는 이전 저장 데이터도 그대로 사용할 수 있습니다.
- 결과 카드에는 실제 설정과 적용·유지 수, 한 글자 살펴보기에는 개별 상태를 보여 줍니다. 글씨나 설정을 바꾸면 이전 전후 비교를 숨기며, 이미 생성한 다운로드는 ‘이전 상태’라고 표시합니다. 최신 설정은 **다시 생성한 TTF**에 반영됩니다. 토글과 두 굵기 설정은 폰트별 프로필이 아닌 현재 브라우저의 필기 설정에 저장되며, 필기 백업에는 포함하지 않습니다. 예전 저장 데이터에 값이 없을 때는 켜짐·100%·100%를 사용합니다.
- 윤곽 재생성과 획·구멍/자모 간 접촉 검사는 512픽셀 격자에 기반합니다. 색칠의 의미를 판단하거나 모든 형태 변화를 발견하지는 못합니다. 작은 획, 겹받침, 복합 모음, 화면과 앱별 작은 글씨를 직접 확인하세요. 입력 단계는 고정 폭이므로 필압은 반영되지 않습니다. 보정 과정은 원래 획·색칠을 수정하지 않습니다.
- 같은 원본 자모와 배치의 보정 결과는 생성 중 재사용합니다. 웹 작업자에서 캔버스를 사용할 수 없으면 본문 캔버스를 이용하는 호환 생성기를 시도합니다. 본문에서도 사용할 수 없으면 보정 없이 만들고 그 사실을 알립니다.

## 폰트 디자인 사용법

1. **폰트 이름**을 입력하면 해당 이름의 설정을 불러옵니다. 새 이름은 직전 설정에서 시작하고, 기존 이름은 저장한 설정을 복원합니다. ‘저장된 설정’ 목록에서도 고를 수 있습니다. 설정은 이 브라우저의 이 주소에 이름별로 저장되며, 필기 자료는 각 설정이 공통으로 사용합니다. 이름을 바꾼다고 완성된 TTF 파일이 따로 저장되는 것은 아닙니다.
2. **획 흔들림 정리**는 기본적으로 꺼져 있습니다. 필요한 만큼 켜고, 자동 또는 펜·터치·마우스 감도를 선택합니다. 원본 입력점과 색칠은 수정하지 않습니다. 새로 쓴 획은 브라우저의 포인터 유형을 기억하고, 예전 획처럼 유형이 없는 데이터는 자동에서 ‘일반’ 감도를 사용합니다. 감도는 임시 휴리스틱이며 하드웨어를 측정하거나 필압을 추정하지 않습니다.
3. **글자 사이 간격**은 글자 advance 폭을 -0.10~+0.20em 변경하며 좌우에 균등하게 나눕니다. 지나치게 좁아지는 글자는 최소 폭을 적용하고 결과에 안내합니다. **띄어쓰기 폭**은 별도로 0.20~1.00em에서 조정합니다. `1em = 1000` 폰트 단위입니다.
4. **세로 정렬·VA**는 각 글자의 윤곽을 기준선에 대해 -0.10~+0.10em 옮깁니다. 양수는 위, 음수는 아래입니다. 이동한 윤곽이 기존 높이를 벗어나면 잘리지 않도록 ascent/descent를 넓히므로 프로그램이나 설정에 따라 줄 높이가 변할 수 있습니다.
5. 미리보기의 위쪽은 기본 간격/높이, 아래쪽은 현재 설정을 기준선에 맞춰 비교합니다. 폰트 생성 전에는 **시스템 글꼴 예시**이고, 생성 후에는 생성된 내 폰트를 기준으로 합니다. 미포함 글자는 기본 글꼴로 대체됨을 표시합니다. 이 화면은 빠른 가이드이며, 조정한 설정으로 **다시 생성한 TTF**와 실제 사용 환경을 꼭 확인하세요. 긴 텍스트는 가이드에서 일부가 생략될 수 있습니다.
6. 정리 전후는 현재 선택한 필기가 있으면 그 획을 보여 주고, 없으면 **가상의 입력 예시**를 보여 줍니다. 슬라이더를 바꾸어도 마지막 TTF는 자동으로 갱신되지 않습니다. 위쪽 ‘폰트 만들기’로 돌아가 다시 생성한 뒤 내려받으세요. 이전 설정의 TTF는 ‘이전 상태 TTF’라고 표시됩니다.

### 흔들림 정리와 안전장치

입력된 획의 짧은 이동 평균을 적용하되, 끝점과 충분히 뚜렷한 방향 전환을 고정하고 그 꺾임을 가로질러 평균을 내지 않습니다. 짧은 점은 그대로 두며 이동 거리를 제한합니다. 감도는 펜·마우스·터치·일반마다 다르게 설정되어 있지만 경험적으로 검증된 기기 보정값은 아닙니다. 기존 입력 렌더러에도 곡선 연결이 적용되어 있어 모든 각진 모서리를 완벽히 보존한다고 보장할 수 없습니다.

폰트 생성 시 사용자 색칠을 정리한 획에 **같은 순서로 다시 적용**합니다. 칠하지 않은 획이 생기거나 필요한 자모가 빠지거나, 자모별 픽셀의 겹침이 부족하거나, 획 덩어리/구멍 수가 바뀌면 **그 글자 전체를 원본으로 유지**하고 결과에 표시합니다. 이 검사는 256픽셀 격자에서의 안전장치이지 의미상 올바른 색칠, 모든 형태 변화 또는 손글씨 품질을 보장하지 않습니다. 자동 브라우저 입력과 가상 데이터로 검사했으며, 실제 필기와 물리 펜·터치 기기 검증은 아직 하지 않았습니다.

### 저장·백업과 다른 주소의 글씨

필기 목록의 **필기 백업**은 완료 전의 획과 색칠도 JSON 파일로 내려받습니다. 폰트 이름·미리보기 문장·폰트별 디자인 설정은 포함하지 않습니다. ‘백업 불러오기’는 이 주소에 아직 필기가 없는 글자만 추가하며 기존 필기를 덮어쓰지 않습니다. 가져오기에는 파일 8MB, 150개 글자, 글자당 4,000개 동작과 동작당 3,000개 입력점 제한이 있습니다.

파일 다운로드가 막힌 내장 화면에서는 ‘다운로드가 막혔다면 · 백업 내용 복사’를 펼쳐 **현재 필기 내용 준비**를 누르고 표시된 전체 내용을 복사해 텍스트 파일로 보관할 수 있습니다. 새로운 작업을 하면 이전에 표시한 백업 내용은 지워지므로 다시 준비해 주세요. 새 탭에서 파일을 불러오거나 맨 아래 ‘다른 주소에 저장한 글씨 가져오기’에 내용을 붙여 넣어 복원할 수 있습니다. 자동 저장이 차단되거나 저장에 실패하면 화면에 경고합니다. 그 경우 새로고침·탭 닫기 전에 백업해야 하며, 백업하지 않고 사라진 필기를 복구한다고 보장할 수 없습니다.

주소가 다르면 `localStorage`는 공유되지 않습니다. ‘다른 주소에 저장한 글씨 가져오기’를 펼쳐, 다른 주소의 개발자 도구 `Application → Local Storage`에서 `geulmoa-drawing-v1`의 Value 전체를 복사해 붙여 넣을 수도 있습니다. 명시적으로 버튼을 눌렀을 때 **현재 주소에 없는 글자만** 이 주소에 추가합니다. 이미 쓴 글씨나 원본 사이트는 덮어쓰지 않고, 이름과 폰트 설정은 가져오지 않습니다. 색칠 미완성 글자는 완성 후에 생성에 사용할 수 있습니다.

### 작업자 오류와 호환 모드

일반 폰트 생성은 웹 워커를 먼저 사용합니다. 시작이 차단되면 별도의 blob 워커를 시도하고, 그것도 시작할 수 없으면 메인 화면에서 실행하는 호환 생성기를 불러옵니다. 워커가 시작됐어도 벡터 보정용 캔버스를 사용할 수 없다면 작업을 시작하기 전 메인 화면의 캔버스 호환 모드로 전환합니다. 본문 캔버스도 사용할 수 없다면 기존 윤곽으로 만들고 결과에 표시합니다. 출처가 불투명한 샌드박스 화면에서는 실패하기 쉬운 워커 호출을 건너뛰고 호환 모드로 진행합니다. 호환 모드는 중간중간 제어를 돌려주지만, 마지막 TTF 인코딩은 동기 처리라 전체 글자 수나 기기 성능에 따라 화면이 수 초 이상 멈출 수 있습니다. 시작 후 실제 생성 중에 오류가 난 경우에는 무조건 재실행하지 않고 오류를 표시합니다. 모든 보안 정책과 브라우저에서 성공한다고 보장하지 않으며, 파일 자체를 불러오지 못하면 서버와 브라우저 설정을 확인해야 합니다.

브라우저의 샌드박스는 폰트 생성과 별개로 자동 저장이나 다운로드를 차단할 수 있습니다. 해당 화면에서 다운로드가 시작되지 않으면 **먼저 필기 내용을 복사해 보관한 후** 새 탭에서 이 사이트를 열고 복원해 다시 생성하세요. 기존에 열려 있던 구버전 화면에는 새 백업 버튼이 없을 수 있으므로, 새로고침하기 전에 기존 저장 데이터를 따로 확보하세요.

## 필기와 글자 조합

1. 글자 목록에서 선택하고 **이 글자 쓰기 시작**을 누르거나 맨 위의 **글씨 쓰기 시작**을 누릅니다. 쓰기 팝업에서 기초 음절을 한 글자씩 평소처럼 한 번에 씁니다. 펜·손가락·마우스를 사용할 수 있습니다.
2. **다음**을 누를 때마다 초성(보라) → 중성(청록) → 종성(주황)의 별도 팝업이 열립니다. 해당 자모의 획 위를 직접 문질러 칠합니다. 각 단계에서 최소한 해당 자모를 칠하고, 마지막 단계에서는 남은 검은 획과 필요한 자모를 모두 칠해야 완료됩니다. 받침이 없으면 종성 단계가 없고 숫자·기호는 색칠 없이 쓰기만 합니다.
3. 팝업 위쪽 단계나 **이전 단계**로 돌아가 수정할 수 있습니다. 색 지우개·되돌리기·색칠만 초기화도 사용할 수 있고, 삭제 전에는 팝업 안에서 다시 확인합니다. 팝업을 닫아도 작성한 획과 색칠은 남으며, 시작 버튼으로 다시 열면 쓰기부터 확인하고 위쪽 단계 버튼으로 원하는 색칠 단계에 갈 수 있습니다. 자동 저장이 막힌 경고가 보이면 새로고침·탭 닫기 전에 필기를 백업하세요.
4. 선택 사항인 ㄱ 문맥 9자, 숫자·기호 또는 원하는 한글 음절을 더 쓸 수 있습니다. 완성되지 않은 음절은 생성에서 제외하고 부족한 자모는 결과에 안내합니다.
5. 직접 쓴 음절을 우선하고 나머지는 수집한 자모 중 문맥이 가까운 형태를 선택하거나 부족한 모양을 추정합니다. 한글을 판독하는 AI 모델은 아니며, 색칠의 의미까지 검증하지 않습니다.
6. 필요한 자모를 모두 확보하면 이론적으로 현대 한글 음절 11,172개를 포함할 수 있습니다. 코드포인트 범위가 완전하다는 뜻이지 모든 글자가 읽기 쉽거나 실제 필체를 복원한다는 뜻은 아닙니다. 영문·옛한글·한자·이모지 및 분해형 자모 셰이핑은 지원하지 않습니다.

필기와 설정은 브라우저 저장소를 지우거나 시크릿 모드를 닫으면 사라질 수 있습니다. 완성 폰트는 TTF로 내려받아 따로 보관하세요. 현재 필압과 속도는 사용하지 않고 고정 획 폭으로 입력합니다.

## GitHub Pages 배포

`.github/workflows/deploy-pages.yml`은 `main` 브랜치가 갱신되면 `site/`를 GitHub Pages로 배포합니다. 소스를 바꾼 뒤에는 `npm ci && npm run build && npm test`를 실행하고 생성된 `site/worker.js`, `site/engine-main.js`도 함께 커밋해야 합니다. 배포 설정의 Pages 소스는 GitHub Actions여야 합니다. HTML과 스크립트의 버전 쿼리(`stroke-ui-2`)를 다음 배포에서도 함께 갱신하면 예전 캐시와 새 생성기가 섞이는 것을 줄일 수 있습니다.
